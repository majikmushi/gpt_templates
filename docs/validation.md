# Validation Model

Validation is a first-class artifact type and now has an executable core.

## Layers

1. **Schema** - required fields, data types, enums, structural constraints.
2. **Semantic** - unique IDs, valid references, relationship endpoints and container membership.
3. **Syntax/serialization** - target parser or structural checks.
4. **Format constraints** - target-specific rules.
5. **Compatibility** - feature/version/renderer support.
6. **Lint** - valid but undesirable patterns.
7. **Runtime/render** - parser or renderer behaviour.
8. **Fixture/regression** - known-valid and known-invalid cases.

## Implemented validation

The Python engine implements:

- canonical JSON Schema Draft 2020-12 validation;
- canonical semantic-reference validation;
- JSON Schema meta-schema validation;
- XML well-formedness validation;
- Mermaid engine-subset structural validation;
- PlantUML wrapper/brace validation;
- UML repository-interchange validation;
- Markdown structural validation.

## Scope boundary

The Mermaid validator is deliberately **not** a normative Mermaid validator. It only validates the subset generated by the engine. The normative validator remains planned for derivation from Mermaid parser grammar, source code, version gates and renderer/runtime behaviour.

Likewise, UML validation currently checks the repository's UML interchange representation, not the full OMG UML metamodel.

This distinction is required so a weak local checker cannot be mistaken for authoritative language validation.
